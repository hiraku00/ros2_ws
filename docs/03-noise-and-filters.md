# 03. センサーのノイズ・チャタリング・フィルタ

本物のセンサーは、同じ場所で測っても、毎回少しずつ違う値を返します。
この文書では、その「ばらつき」が起こす問題と、2 つの対策を、実測の数字つきで説明します。

## 1. ノイズとは

**ノイズ** = 測定値に混ざる、ランダムな誤差です。

`sim_robot` は、送る距離に **±0.5 のランダムな誤差**を足します（画面の「壁まで」は、真の値です）。

```
真の距離 3.0 のとき、brain に届く値の例:  2.7  3.4  2.9  3.1  2.6  3.3 …
                                         └ 2.5 〜 3.5 の間でばらつく ┘
```

誤差を足すのは、**brain に送る値だけ**です。本物のセンサーも、ロボットの真の位置は変わらず、測定値だけがぶれるからです。

> **ノイズの全幅**：±0.5 なら、ぶれる範囲の全体は 1.0（−0.5 〜 +0.5）です。この文書では「全幅」と呼びます。

## 2. チャタリングとは

**チャタリング** = 測定値が判断の境界線のそばで揺れて、**判断が短い間隔で行ったり来たりする**現象です。
もとは、スイッチの接点が「カチカチカチ」と細かく入り切りを繰り返す現象を指す電子工学の言葉です。

境界は `turn_distance = 3.0` です。真の距離が 2.9 のとき、ノイズでこうなります。

| 測定値 | brain の判断 |
|---|---|
| 2.8 | `STOP`（3.0 未満） |
| 3.2 | `SLOW`（3.0 以上） ← 本当は止まっているべきなのに |
| 2.7 | `STOP` |

実際のログでは、こう見えます。

```
壁まで= 2.5  指示=STOP
壁まで= 2.5  指示=SLOW    ← 1 回だけ SLOW が混ざる
壁まで= 2.5  指示=STOP
```

### なぜ困るのか

1. **STOP の 2 秒タイマーが、リセットされる。** 離れたと判断すると、覚えた時刻を忘れる（[02](02-robot-exercise.md#5-stop-の-2-秒を数える仕組み)）ため、STOP が 4 秒以上続くこともある。
2. **`SLOW` のたびに少し前進する。** チャタリングで SLOW が混ざるたびに、ロボットが壁へ近づく。

| ノイズ対策 | 壁への最接近（平均、真の距離） |
|---|---|
| なし | **2.50** |
| ヒステリシス（後述） | **3.00** |

ノイズ対策をしないと、ロボットは壁に近づきすぎます。

## 3. 対策1 移動平均フィルタ

**直近 N 個の測定値の平均**で判断します（`brain.py` では N = 5）。ノイズはプラスにもマイナスにも出るので、平均すると打ち消し合います。

```python
self.history = deque(maxlen=5)               # 直近 5 個だけ覚える入れ物
self.history.append(msg.data)                # 新しい値を足す（古い値は自動で消える）
dist = sum(self.history) / len(self.history) # 平均
```

### 弱点：反応が遅れる

平均には**過去の値**が混ざります。壁に近づいているとき、過去の値は「今より遠い」ので、平均は真の距離より大きくなります。
つまり、**壁が実際より遠いと誤解して、止まるのが遅れます**（危ない方向）。

| N | チャタリングの割合※ | STOP を始める距離（真値の平均） | 最接近 |
|---|---|---|---|
| 1（平均なし） | 95.4% | 3.00 | 2.50 |
| 3 | 35.7% | 2.70 | 2.59 |
| **5（採用）** | **1.6%** | **2.50** | **2.49** |
| 10 | 0.0% | 2.00 | 2.00 |
| 20 | 0.0% | **0.58** | **0.58** |

※ STOP の途中で SLOW に戻ってしまった割合（ヒステリシスなし、ノイズ ±0.5、5000 回の平均）。

実機ログでも、N = 20 では壁まで 0.4 で STOP が始まり、ほぼ激突でした。

> **N を大きくするほど、ノイズは減るが、反応が遅れて危なくなる。**
> フィルタの強さは、ロボットの速さと、許される安全距離から決めます。

## 4. 対策2 ヒステリシス

**ヒステリシス** = 状態を切り替える**境界線を、「入るとき」と「出るとき」でわざとずらす**仕組みです。

### たとえ：エアコン

| | 動き |
|---|---|
| ヒステリシスなし | 26.0℃ を超えたら ON、下回ったら OFF。25.9 と 26.1 の間でふらつくと、1 秒ごとに ON/OFF が入れ替わる |
| ヒステリシスあり | 26.5℃ を超えたら ON、**25.5℃ を下回るまで OFF にしない** |

### この演習での 2 本の線

```
壁 ◀── 0 ───────── 3.0 ───────── 4.0 ─────────────▶ 遠い
                  ①入る線        ②出る線
                    │               │
          STOP を始める    これより遠くなるまで
          （位置はここで決まる）  STOP をやめない
```

| 線 | 値 | 役割 |
|---|---|---|
| ① 入る線 | `turn_distance`（3.0） | STOP を**始める**距離。止まる位置は、これで決まる |
| ② 出る線 | `turn_distance + hysteresis`（4.0） | STOP を**やめる**条件。止まったあとにだけ関係する |

3.0〜4.0 の間は「今の状態を続ける」ので、ノイズで 3.2 や 3.5 に見えても、STOP が途切れません。

```python
threshold = turn + hysteresis if self.stop_started is not None else turn
if dist < threshold:
    ...   # STOP / TURN
```

- `stop_started` が `None` でない = 今 STOP 中 → 出る線（4.0）を使う
- `None` = まだ STOP していない → 入る線（3.0）を使う

### 幅の決め方

**出る線は、入る線から「ノイズの全幅」以上、離します。**

```
入る線 3.0  +  ノイズの全幅 1.0  =  出る線 4.0
```

STOP に入るとき、ノイズが −0.5 ぶれていると、真の距離は最大 3.5 まで遠い場合があります。
その状態で STOP 中にノイズが +0.5 ぶれると、測定値は 4.0 になります。出る線が 4.0 未満だと、ここで抜けてしまいます。

| 出る線までの幅 `hysteresis` | STOP が途中で中断した割合※ | 最接近 |
|---|---|---|
| 0（なし） | 95.2% | 2.50 |
| 0.5 | 38.5% | 2.86 |
| **1.0（採用）** | **0.0%** | **3.00** |
| 2.0 | 0.0% | 3.00 |

※ 平均なし（N = 1）、ノイズ ±0.5。0.5 では足りず、1.0 で 0% になります。

### 何が変わって、何が変わらないか

| | ヒステリシスなし | あり（1.0） |
|---|---|---|
| STOP を**始める**距離 | 約 3.0 | 約 3.0（同じ） |
| ロボットが**最終的に止まった**位置（最接近） | 2.50 | **3.00** |
| STOP の途中の SLOW | 混ざる | 混ざらない |

始める距離は変わりませんが、チャタリングで SLOW が混ざらなくなるため、最終的に壁から遠い位置で止まれます。

### ヒステリシスは「境界ごと」に入れる

ヒステリシスは、**入れた境界の揺れしか止められません。** この演習には、判断の境界が 2 つあります。

| 境界 | 切り替わる判断 | 入る線 | 出る線（入る線 + `hysteresis`） |
|---|---|---|---|
| ① STOP の境界 | `SLOW` ↔ `STOP` | 3.0 | 4.0 |
| ② SLOW の境界 | `FORWARD` ↔ `SLOW` | 8.0 | 9.0 |

```
壁 ◀── 0 ─── 3.0 ─── 4.0 ─────────── 8.0 ─── 9.0 ──────────▶ 遠い
        STOP     │       SLOW           │       FORWARD
                ①の帯                  ②の帯
          （この中では状態を続ける）  （この中では状態を続ける）
```

最初は、①にだけ入れていました。②が未対策のままだと、`SLOW ↔ FORWARD` の揺れが残ります。

```
壁まで= 8.1  指示=SLOW
壁まで= 7.6  指示=FORWARD    ← 8.0 付近で、また FORWARD に戻る
壁まで= 7.4  指示=SLOW
```

| 設定（平均なし N=1、`hysteresis` 1.0） | 8.0 付近で、SLOW から FORWARD に戻った割合 |
|---|---|
| ②に入れない | **18.8%**（約 5 回に 1 回の壁で発生） |
| ②に入れる（現在） | **0.0%** |

#### ②の実装

①と同じ形です。違うのは、「今、その状態にいるか」を知る方法です。

| | 「今その状態か」の判断 | 理由 |
|---|---|---|
| ① STOP | `self.stop_started is not None` | `stop_started` は、`None` か時刻（時刻を覚える変数が、状態の目印を兼ねる） |
| ② SLOW | `self.slowing`（`True` / `False`） | SLOW には、覚える時刻がないので、専用の目印を持つ |

```python
self.slowing = False   # __init__ で 1 回だけ作る（on_distance の中で作ると、毎回 False に戻ってしまう）

slow_threshold = slow + hysteresis if self.slowing else slow
...
elif dist < slow_threshold:
    self.slowing = True      # SLOW に入ったら True
    cmd = 'SLOW'
else:
    self.slowing = False     # FORWARD に戻ったら False
    cmd = 'FORWARD'
```

`STOP` / `TURN` のときは、`self.slowing` を更新しません。STOP が終わると、ロボットは壁の近くから出発するので、
次の `SLOW` / `FORWARD` の判断は、これまでの値のままで正しく進みます。
`TURN` のあとは、距離が大きく跳ねて 9.0 を超えるので、`FORWARD` になり、`slowing` が `False` に戻ります。

#### よくある書き間違い

| 書き方 | 何が起きるか |
|---|---|
| `slow_threshold = (self.slowing) ? slow + hysteresis : slow` | `? :` は Python にない書き方。`SyntaxError` で起動しない（正しくは `A if 条件 else B`） |
| `self.slowing = False` を `on_distance` の先頭に書く | 毎回 `False` に戻り、覚えていられない。変更前と同じ動きになる |
| `... if self.slowing is not None else slow` | `self.slowing` は `None` にならない（`True` / `False`）ので、常に 9.0 を使い、SLOW に入る線まで 9.0 になる。`is not None` は、`None` かどうかで状態を表す変数（`stop_started`）にだけ使う |

#### 実機のコードで確かめる

`sim_robot` を使わずに、本物の `brain` へ距離を直接送るテストがあります。
真の距離を 8.0〜9.0 の帯の中（8.3）に置き、ノイズ ±1.0 を載せて、指示が切り替わった回数を数えます。

```bash
# コンテナの中で（source 済み）
python3 tools/probe_brain_slow_band.py
```

| `hysteresis` | 帯の中で、SLOW ↔ FORWARD が切り替わった回数（300 回送信） |
|---|---|
| 0.0 | 31 回（乱数で変わる。数十回） |
| 1.0 | **0 回**（ずっと `SLOW`） |

> **このテストが専用の `ROS_DOMAIN_ID` を使う理由：** 動いている他の `brain` が、同じ `cmd` トピックに書き込むと、結果が混ざります。
> 実際、最初に混ぜて実行したときは、`hysteresis=1.0` でも 21 回と出ました。
> ドメイン ID が違うノード同士は、お互いが見えません。

## 5. どう使い分けるか

| | 移動平均 | ヒステリシス |
|---|---|---|
| 何を減らすか | 値そのもののばらつき | 判断の入れ替わり |
| 弱点 | 反応が遅れ、壁に近づく | 値のばらつきは減らない |
| 効きやすい場面 | 値をきれいにしたいとき | 状態を切り替える判断 |

実機では**両方を組み合わせる**のが一般的です。この演習の採用値は、平均 N = 5 とヒステリシス 1.0 です。

`hysteresis` は、①STOP の境界と②SLOW の境界の**両方で共有**しています。ノイズの大きさが同じなので、必要な幅も同じです。
センサーや境界ごとにノイズが違う場合は、パラメータを分けます。

### ノイズが大きいとき

| ノイズ | ヒステリシスのみ（H = 1.0） | 平均のみ（N = 5） |
|---|---|---|
| ±0.2 | 0.0% | 0.0% |
| ±0.5 | 0.0% | 1.7% |
| ±1.0 | **63.1%** | 27.0% |

ノイズが ±1.0（全幅 2.0）になると、幅 1.0 では足りません。**幅は、ノイズの全幅に合わせて広げます。**

## 6. 実験：ヒステリシスの効果を、自分の目で見る

`hysteresis` はパラメータなので、実行中に切り替えられます。

効果をはっきり見るため、まず `brain.py` の `deque(maxlen=5)` を一時的に `maxlen=1`（平均なし）にして、brain を起動し直します。

```bash
ros2 param set /brain hysteresis 0.0   # チャタリングが出る
ros2 param set /brain hysteresis 1.0   # チャタリングが消える
```

見る場所は 2 か所です。

| 場所 | 揺れ方 | ヒステリシス 0.0 のとき | 1.0 のとき |
|---|---|---|---|
| 壁まで 3.0 付近 | `STOP` の途中に `SLOW` が混ざる | ほぼ毎回 | 出ない |
| 壁まで 8.0 付近 | `SLOW` のあとに `FORWARD` が混ざる | 約 5 回に 1 回の壁 | 出ない |

8.0 付近は、出る確率が低いので、**1 回の壁で出なくても、効いたとは言えません**。0.0 と 1.0 のログを並べて比べるか、
上の `tools/probe_brain_slow_band.py` で、確率の低い現象を、数百回まとめて確かめます。

N = 5 のままでは、平均がすでにノイズを抑えるので、差が見えにくい（0% と約 1.6%）です。
確認が終わったら、`maxlen=5` に戻してください。

## 7. 数字を自分で再現する

| ツール | 実行する場所 | 何を確かめるか |
|---|---|---|
| [tools/simulate_filters.py](../tools/simulate_filters.py) | Mac のターミナル（ROS 2 不要） | この文書の表の数字。`brain.py` の判断ロジックを再現して、数千回シミュレートする |
| [tools/probe_brain_slow_band.py](../tools/probe_brain_slow_band.py) | コンテナの中（`source` 済み） | **本物の** `brain` が、SLOW の出る線（9.0）で、揺れを止めるか |

```bash
python3 tools/simulate_filters.py          # Mac で
python3 tools/probe_brain_slow_band.py     # コンテナの中で
```

2 つは、見ているものが違います。前者は「考え方の検証」、後者は「実際に書いたコードの検証」です。
**ロジックを再現した模擬実験が合っていても、本物のコードに書き間違いがあれば、動きません。** 両方で確かめておくと安心です。

## 用語集

| 用語 | 意味 |
|---|---|
| ノイズ | 測定値に混ざるランダムな誤差 |
| ノイズの全幅 | ぶれる範囲の、最大と最小の差（±0.5 なら 1.0） |
| チャタリング | 境界のそばで、判断が短い間隔で入れ替わる現象 |
| 移動平均 | 直近 N 個の値の平均 |
| ヒステリシス | 入る境界と出る境界を、わざとずらす仕組み |
| 遅れ（レイテンシ） | 実際の変化が、判断に反映されるまでの時間 |
| トレードオフ | 片方を良くすると、もう片方が悪くなる関係 |
