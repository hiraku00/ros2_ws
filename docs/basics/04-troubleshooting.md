# 04. つまずきやすい点と対処（入門編）

> **この章でわかること**
>
> - 入門編で、実際に起きた「あれ？」と、その直しかた
> - 「コードを変えたのに、動きが変わらない」の正体
> - コードの書きまちがいと、実験の結果がおかしいときの調べかた

## 1. 環境のエラー

| こうなったら | 原因 | こうする |
|---|---|---|
| `failed to connect to the docker API ... docker.sock` | Docker Desktop が動いていない | Docker Desktop を起動して、メニューバーにクジラが出るまで待つ。そのあと `docker start ros2` |
| `container ... is not running` | コンテナが止まっている | `docker start ros2` |
| `ros2: command not found` | `source` していない。または、Mac 側で打った | プロンプトが `root@...:/#` か見る。コンテナの中で `source /opt/ros/jazzy/setup.bash` |
| `cd: /root/ros2_ws does not exist` | Mac 側で打った | `docker exec -it ros2 bash` で、コンテナに入ってから |
| `Unsupported use of '='`（fish） | Mac 側（fish）で、コンテナ用の `source` を打った | コンテナの中で打つ |
| `Node not found`（`ros2 param set` のとき） | 相手のノードが動いていない | `ros2 node list` で、`/brain` があるか見る |

Mac 側とコンテナの中の見分けかたは、[01 の 3 章](01-ros2-basics.md#3-なぜ-docker-を使うのか)を見てください。

### コンテナに入るたびの `source` を、はぶく

コンテナの中で、1 回だけ打ちます。

```bash
echo 'source /opt/ros/jazzy/setup.bash' >> ~/.bashrc
echo 'source /root/ros2_ws/install/setup.bash' >> ~/.bashrc
```

これは、**コンテナの中**の設定です。Mac の fish とは別です。コンテナを消す（`docker rm`）と、消えます。

## 2. 「コードを変えたのに、動きが変わらない」

いちばん多いつまずきです。

| 原因 | 説明 |
|---|---|
| **ノードを起動し直していない** | 動いているプログラムは、**起動したときのコードのまま**動き続ける。保存しただけでは、変わらない |
| `--symlink-install` のかんちがい | 「ビルドし直さなくてよい」という意味。「起動し直さなくてよい」ではない |

**たとえ**：ゲームのセーブデータを書きかえても、いま遊んでいるゲームの画面は変わりません。一度終わって、もう一度始めると、変わります。

### 確かめかた

```bash
ps -eo lstart,args | grep "[l]ib/my_first_pkg"
```

| 出てきた起動時刻 | 意味 |
|---|---|
| ファイルを保存した時刻より**前** | 古いコードで動いている → Ctrl+C で止めて、`ros2 run ...` し直す |
| 保存した時刻より**あと** | 新しいコードで動いている |

`sim_robot` と `brain` は、別々のプログラムです。**変えたほうだけ**、起動し直します。

### ビルドが必要なとき

| 変えたもの | ビルド | 起動し直し |
|---|---|---|
| Python のコード（`--symlink-install` でビルド済み） | いらない | **いる** |
| `setup.py` の `entry_points`（ノードを足した） | **いる** | いる |

```bash
cd /root/ros2_ws
colcon build --symlink-install --packages-select my_first_pkg
source install/setup.bash
```

## 3. 「頭がいないのに、ロボットが勝手に動く」

**前の実験のノードが、裏で残っています。**

```bash
ps -eo pid,args | grep "[l]ib/my_first_pkg"
```

残っていたら、そのタブで Ctrl+C を押すか、出てきた番号（PID）を指定して `kill <番号>` で止めます。

> **注意：`pkill -f my_first_pkg` は使わないでください。** コマンドの文字そのものにも `my_first_pkg` が入っているので、コンテナのシェルまで止めてしまい、コンテナが止まったことがあります。

## 4. コードの書きまちがい

実際に書きまちがえた例です。

| 書きかた | 起きること | 正しくは |
|---|---|---|
| `x = (条件) ? a : b` | 動かない（`SyntaxError`）。`? :` は C や JavaScript の書きかた | `x = a if 条件 else b` |
| `on_distance` の先頭で `self.slowing = False` | メッセージのたびに `False` にもどり、覚えられない | 覚えたい変数は、`__init__` で 1 回だけ作る |
| `if self.slowing is not None` | `True` も `False` も `None` ではないので、いつも真 | `if self.slowing` |
| `self.stop_started` に時刻を入れ忘れる | `None` から数を引いて、`TypeError`。`brain` が止まる | 初めて近づいたときに、`now` を入れる |
| 判断に使う値が、`msg.data` と `dist` でまざる | 一部の判断だけ、ノイズに弱いまま | 判断に使う値は、1 つの変数にそろえる |

`is not None` は、**`None` かどうかで状態を表す変数**（`self.stop_started`）にだけ使います。

### 文法だけを、すばやく確かめる

```bash
python3 -c "import ast; ast.parse(open('src/my_first_pkg/my_first_pkg/brain.py').read()); print('ok')"
```

文法のまちがいは、これで分かります。ただし、**動きが正しいかまでは、分かりません**（上の `is not None` の例は、文法は正しいのに、動きがまちがっています）。

## 5. 実験の結果が、おかしいとき

| こうなったら | 原因 | こうする |
|---|---|---|
| 同じ設定なのに、結果がまざる | 同じトピックに、複数の `brain` が書いている | 3 章の方法で、残っているノードを探して止める |
| テストの結果が、手で動かした結果と合わない | テストと手のノードが、同じグループ（ドメイン）にいる | テストは `ROS_DOMAIN_ID` を別の番号にする（`tools/probe_brain_slow_band.py` はそうしている） |
| たまにしか起きない現象（約 18%）が、1 回の壁で出ない | 出なかっただけで、直ったとは限らない | 数百回まとめて試す（`tools/` のスクリプト）。対策のあり・なしを並べてくらべる |

## 6. ログの読みかた

```
|..............>..........................| 壁まで= 9.5  指示=FORWARD
```

| 部分 | 意味 |
|---|---|
| `>` か `<` | ロボットの位置と向き（右向きか、左向きか） |
| 壁まで | 向いている方の壁までの、**本当の**距離（ノイズなし） |
| 指示 | `brain` から届いた、最新の指示 |

「壁まで」にはノイズが入っていません。`brain` は、ノイズ入りの値で判断しているので、少しずれて見えることがあります。

## 7. 実験のコツ

| コツ | 理由 |
|---|---|
| 先に予想を書いてから、動かす | 結果とのちがいが、いちばんの勉強になる |
| 1 回のログで、結論を出さない | ノイズはばらばらなので、2〜3 周は見る |
| 一度に 1 つだけ変える | 何が効いたのか、分からなくなる |
| 変えた値は、実験のあとで元にもどす | 次に起動したとき、思わぬ設定で動く |

## まとめ

| 困ったら | まず見る所 |
|---|---|
| コマンドが見つからない | プロンプト（Mac 側か、コンテナの中か） |
| 動きが変わらない | ノードの起動時刻と、ファイルを保存した時刻 |
| 勝手に動く・結果がまざる | 裏に残っているノード（`ps`） |
| たまにしか起きない | 1 回で決めず、何百回もまとめて試す |

## 用語集

| 用語 | 意味 |
|---|---|
| PID | 動いているプログラム 1 つ 1 つに付く番号 |
| `source` | 「この設定を読みこんで」という命令。`ros2` を使えるようにする |
| ビルド | コードを、動かせる形にすること（`colcon build`） |
| ドメイン ID（`ROS_DOMAIN_ID`） | 同じ番号のノードどうしだけが話せる。実験を分けるのに使う |
