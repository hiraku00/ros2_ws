# 04. つまずきやすい点と対処（ステップ 2）

ステップ 2 の、フェーズ 1 で実際に起きたことと、その対処をまとめます。
環境のエラー（Docker が止まっている、`source` し忘れ、など）は、入門編の [04](../basics/04-troubleshooting.md) を見てください。

## 1. 数字の意味のつまずき

| 症状・疑問 | 原因 | 対処・考え方 |
|---|---|---|
| 「`x=0.5` だから、0.5 m ずつ進むのでは？」 | 0.5 は**速さ**（m/秒）。1 歩（0.1 秒）では 0.05 m | 速さ × 時間 = 距離。単位（m/秒）を見る |
| 「壁まで行ったのに、`x=20` にならない」 | ロボットは半径 0.3 m の円。中心は、壁から 0.3 m 以内に入れない | 壁に近づける限界は、壁 − 半径（20 − 0.3 = 19.7） |
| 「19.7 ではなく、19.65 で止まる」 | 1 歩 0.05 m を足していくと、小数の誤差で、19.7 をわずかに超える | 小数の、ぴったりの値は、比べない（[03 実験 2](03-experiments.md#予想とずれた理由)） |
| 「0.3 m は、直径か、半径か」 | **半径**。直径は 0.6 m | 図の青い丸は、半径 0.3 m で描かれている（1 m = 30 ピクセル） |
| 「なぜ回転が出てくるのか」 | 前進だけでは、壁で止まるだけ。よけるには、向きを変える必要がある | `angular.z` が 0 でなければ、その場で回る（[01](01-lidar-and-twist.md#4-cmd_veltwist-速さで指示する)） |
| 「`ranges` が 360 個なのは、365 ではないのか」 | 角度の 1 周が 360°。365 は 1 年の日数 | 1° ごとに 1 本 |

## 2. 「図が、思ったとおりに見えない」

| 症状 | 原因 | 対処 |
|---|---|---|
| ブラウザが真っ白、または、ファイルがない | `room_sim` を起動していない（図は、起動した 1 秒後から書き出される） | タブ 1 で `ros2 run room_robot_pkg room_sim`。`ls ~/Practice/ros2_ws/output` で確認 |
| 図が動かない | `room_sim` が止まっている。または、ロボットが止まっているだけ（指示が途絶えた、壁にいる） | タブ 1 のログと、左上の `x`、`y`、`θ` の数字が変わるかを見る。変わらないなら、ブラウザを手で再読み込みする |
| 灰色の線ばかりで、赤い線がない | まわり 12 m 以内に、何もない（`inf`） | 正常。壁に近づくと、赤くなる |
| ロボットが、ほんの少し動いて、止まる | `/cmd_vel` を送り続けていない（`-r 10` を付けずに、1 回だけ送った） | `-r 10` を付けて、送り続ける。最後の指示から 0.5 秒で止まる仕様 |
| ロボットが、前に進まない（壁の目の前） | 位置の更新が取り消されている（壁にめり込むため） | 回れば、向きは変えられる。`angular.z` を送る |
| `x=10.00 y=10.00` に戻った | `room_sim` を、再起動した。位置は、変数にしか持っていない | 正常。再起動すると、開始位置 (10, 10)、向き 0° に戻る |

## 3. 「動きが、計算と少し合わない」

| 症状 | 原因 | 対処・考え方 |
|---|---|---|
| `timeout 6.28` で回したのに、180° ではなく 172° | `ros2 topic pub` の起動に、約 0.7 秒かかる（56 メッセージだけ送られる）。さらに、最後の指示を 0.5 秒保持する | 「送った時間」と「動いた時間」は違う（[03 実験 3](03-experiments.md#172-の理由)） |
| `publishing #143` で、距離を計算した | メッセージの数は、止まったあとも増える | 距離は、位置の差（`x=` の変化）や、距離 ÷ 速さで出す |

## 4. 作り方のつまずき（パッケージを作るとき）

| 症状 | 原因 | 対処 |
|---|---|---|
| `ros2 pkg create` で `the following arguments are required: package_name` | `--dependencies` の後ろに、パッケージ名を置いたため、依存パッケージの名前と、みなされた | **パッケージ名を先に**書く。`ros2 pkg create room_robot_pkg --build-type ament_python --dependencies rclpy sensor_msgs geometry_msgs` |
| `ros2 run room_robot_pkg room_sim` で、`No executable found` | `setup.py` の `entry_points` に登録していない、または、ビルドし直していない | `setup.py` の `console_scripts` に `'room_sim = room_robot_pkg.room_sim:main'` を足して、`colcon build` と `source install/setup.bash` |

## 5. プロセスの後始末（テストで、特に大事）

動いているノードは、止めない限り、裏で残り続けます。残ったノードは、あとの実験に混ざります。

| 注意 | 理由・やりかた |
|---|---|
| 起動時刻で、自分のものか見分ける | `ps -eo pid,lstart,args \| grep "[r]oom_sim"`。複数見つかったら、起動時刻が古いものを、先に疑う |
| **`pkill -f` は、使わない** | コマンド文字列にも一致して、コンテナのシェルを巻き込み、コンテナが止まったことがある。**PID を指定して、`kill` する** |
| テスト用は、`ROS_DOMAIN_ID` を変える | 同じドメインだと、別のノードと、メッセージが混ざる（例: `export ROS_DOMAIN_ID=42`）。あなたのノードは、変えずに（0 のまま）使う |
| `ros2 run` の PID に注意 | `ros2 run ...  &` で得られる PID は、起動役（ラッパー）のもの。本体の `room_sim` が、残ることがある。確認してから止める |

## 用語集（このフェーズで出てきたもの）

| 用語 | 意味 |
|---|---|
| 積分 | 速さを、時間をかけて足し合わせて、位置を出すこと |
| レイキャスト | 線（レーザー）を伸ばして、最初にぶつかるものまでの距離を求める方法 |
| `cmd_timeout` | 指示が途絶えたら止まる、安全装置の時間 |
| ドメイン ID（`ROS_DOMAIN_ID`） | 同じ値のノードどうしだけが、通信する。実験を分けるために使う |
