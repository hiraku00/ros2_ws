# 02. room_sim の仕組み（部屋・LiDAR・図）

`room_sim` は、**ロボットの体と、部屋の世界**を受け持つノードです。コードは [room_sim.py](../../src/room_robot_pkg/room_robot_pkg/room_sim.py) です。
世界のシミュレーションは、学習の本筋ではないので、先に作ってあります。仕組みを知っておくと、あとで頭脳を作るときに役立ちます。

## 1. 受け取るもの・送り出すもの

| 向き | トピック | 型 | 中身 |
|---|---|---|---|
| 受け取る | `/cmd_vel` | `Twist` | 前進の速さ、回る速さ |
| 送り出す | `/scan` | `LaserScan` | 360 本のレーザーの距離（10 回/秒） |
| 書き出す | `output/index.html`、`output/room.svg` | ファイル | 部屋の図（1 回/秒） |

## 2. 世界のきまり

| 項目 | 値 |
|---|---|
| 部屋 | 20 m × 20 m の四角。左下が (0, 0)、右上が (20, 20) |
| 単位 | 長さは m、角度は rad、時間は秒 |
| 障害物 | 円が 1 つ（中心 (3, 13)、半径 1.5）、四角が 1 つ（x: 14〜17、y: 2〜5） |
| ロボット | 半径 0.3 m の円。開始位置は部屋の真ん中 (10, 10)、向きは +x（右） |
| 向き `theta` | 0 が右向き。反時計回りに増える |

ロボットは、点ではなく、**半径 0.3 m の円**です（直径 0.6 m）。だから、壁に中心が 0.3 m より近づくことはできません。

## 3. 1 歩の流れ（0.1 秒ごと）

タイマーが 0.1 秒ごとに、次の順で処理します（`step` 関数）。

```
1. 最後の指示から 0.5 秒たっていたら、速さを 0 にする（暴走防止）
2. 向きを更新:   theta += 回る速さ × 0.1
3. 位置を更新:   x += 前進の速さ × cos(theta) × 0.1
                 y += 前進の速さ × sin(theta) × 0.1
4. 壁や障害物にめり込むなら、位置の更新は取り消す
5. 360 本のレーザーを計算して、/scan に送る
```

### 3.1 位置の更新（Twist を足していく）

`Twist` は「速さ」なので、**時間をかけて足し合わせる**と、位置になります。これを「積分」と呼びます（中学の「速さ × 時間 = 距離」と同じです）。

```
向きが 0°（右）   → x だけが増える（cos 0° = 1、sin 0° = 0）
向きが 90°（上）  → y だけが増える（cos 90° = 0、sin 90° = 1）
向きが 45°        → x も y も、同じだけ増える
```

### 3.2 めり込みを防ぐ

次の位置にロボット（円）を置くと、壁や障害物に触れる場合は、**位置の更新だけ取り消します**（向きの更新は、そのままです）。
だから、壁に当たったあとも、その場で回れば、向きを変えられます。

| 触れ方の判定 | 内容 |
|---|---|
| 壁 | 中心が、壁から 0.3 m 以内に入るか |
| 円の障害物 | 中心と円の中心の距離が、「円の半径 + 0.3」より小さいか |
| 四角の障害物 | 四角の、中心にいちばん近い点との距離が、0.3 より小さいか |

### 3.3 回り始め・やめた瞬間のログ

`angular` が 0 から 0 以外へ（またはその逆へ）変わった**瞬間だけ**、位置をログに出します（毎回は出しません）。

```
[room_sim]: 回り始めた: x=18.52 y=10.00 θ=3°
[room_sim]: 回るのをやめた: x=18.54 y=10.02 θ=40°
```

図は 1 秒おきの更新で、ロボットは 1 秒に 0.3 m 進むため、図では「どこで回り始めたか」を見失います。ログなら、その瞬間の位置が、正確に分かります。

### 3.4 暴走防止（`cmd_timeout`）

`/cmd_vel` は、**「いま、この速さで」という指示を、送り続ける**ものです。
最後の指示から 0.5 秒（`cmd_timeout`）たつと、速さを 0 にして、止まります。

頭脳のノードが止まったり、通信が切れたりしたとき、ロボットが、最後の指示のまま走り続けないための、安全装置です。実機の多くも、同じ仕組みを持っています。

## 4. LiDAR のまねかた（レイキャスト）

1 本のレーザーを、「ロボットの位置から、ある向きにのびる、まっすぐな線」と考えます。
その線が、**最初にぶつかるもの**までの距離を求めます。

```
        ╲   壁（線分）
   🤖────╲──→
          ╲
```

| ぶつかる相手 | 求めかた |
|---|---|
| 壁、四角の辺（線分） | 線と線の交点を求める（連立方程式） |
| 円の障害物 | 線と円の交点を求める（二次方程式の解） |

壁 4 本、四角の 4 辺、円 1 つの、すべてに対して距離を計算して、**いちばん近いもの**を答えにします。これを 360 本分、繰り返します。

### 4.1 `inf` になるとき

| 条件 | 結果 |
|---|---|
| 答えが `range_max`（12 m）より遠い | `inf` |
| 答えが `range_min`（0.1 m）より近い | `inf` |
| どこにもぶつからない | `inf` |

開始位置 (10, 10) で、360 本のうち **70 本が `inf`** でした（実測）。部屋の四隅の方向（斜め）は、壁までの距離が 12 m を超える（角で 14.14 m）ためです。四角の障害物が、そのうちの数本をさえぎるので、計算上の全部の本数よりは少なくなります。

### 4.2 ノイズ（`noise` パラメータ）

`noise` を 0 より大きくすると、**測れた距離**に、`±noise` の範囲の乱数を足します。`inf` には、足しません。
初期値は 0.0（ノイズなし）です。フェーズ 3 で、この値を上げて、チャタリングを 2D で起こします。

## 5. 図（SVG）の見かた

1 秒ごとに、`output/room.svg` と `output/index.html` を書き出します。
`index.html` は、1 秒ごとにページを読み直す設定になっているので、ブラウザで開いておくと、動きが見えます。

```
file:///Users/hiraku/Practice/ros2_ws/output/index.html
```

| 見えるもの | 意味 |
|---|---|
| 青い丸 | ロボット（半径 0.3 m）。濃い青の線が、向き |
| 茶色の丸と四角 | 障害物 |
| **赤い線** | 壁や障害物に、レーザーが当たった |
| **灰色の線** | 12 m 以内に何もなかった（`inf`） |
| 左上の数字 | ロボットの位置と向き（`x`、`y`、`θ`） |

見やすさのため、線は、5 本に 1 本（72 本）だけ描いています。

### 図の座標

部屋の座標は、「上が +y」ですが、SVG は、「下が +y」です。そのため、描くときに、y を上下反転しています（`sy` 関数）。
1 m = 30 ピクセルで描くので、図の大きさは 600 × 600 です。

> 書き出しのとき、まず別の名前のファイルに書いてから、名前を付け替えています。ブラウザが、書きかけのファイルを読んでしまうのを防ぐためです。

## 6. パラメータ

実行中に `ros2 param set /room_sim <名前> <値>` で変えられます（毎回、読み直しているため）。

| 名前 | 初期値 | 意味 |
|---|---|---|
| `noise` | 0.0 | `ranges` に足す乱数の幅（±noise）。フェーズ 3 で使う |
| `range_max` | 12.0 | 測れる最大距離（m）。これより遠いと `inf` |
| `cmd_timeout` | 0.5 | この秒数、`/cmd_vel` が来なければ止まる |
| `output_dir` | `/root/ros2_ws/output` | 図の書き出し先 |

`range_max` を変えると、灰色の線（`inf`）の数が変わります。試してみてください。

```bash
ros2 param set /room_sim range_max 20.0
ros2 param set /room_sim noise 0.5
```

| 設定 | 実測 |
|---|---|
| 初期値（`range_max` 12.0） | `inf` が 70 本。`ranges[0]` = 10.0 |
| `range_max` 20.0 | `inf` が **0 本**（どの角も、14.14 m ≦ 20 m で届く） |
| さらに `noise` 0.5 | `ranges[0]` が、9.553、9.553、9.895 のように**毎回変わる**（正しい値は 10.0） |

## 7. 動かしかた

Ghostty のタブを使います。コンテナに入るには、タブごとに `docker exec -it ros2 bash` を実行します。

```bash
# タブ 1: シミュレータ
ros2 run room_robot_pkg room_sim

# タブ 2: 手で動かす（Ctrl+C で止める）
ros2 topic pub -r 10 /cmd_vel geometry_msgs/msg/Twist "{linear: {x: 0.5}, angular: {z: 0.0}}"

# タブ 3: /scan を見る
ros2 topic echo /scan --once --field angle_increment
ros2 topic echo /scan --once --field range_max
```

ビルドは、初回と、`setup.py` を変えたときだけ必要です。

```bash
cd /root/ros2_ws
colcon build --symlink-install --packages-select room_robot_pkg
source install/setup.bash
```

> **`room_sim` を再起動すると、ロボットは開始位置 (10, 10)、向き 0° に戻ります。** 位置は、メモリ（変数）にしか持っていないためです。
