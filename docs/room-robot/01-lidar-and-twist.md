# 01. 2D の部屋の掃除ロボット（目的と、2 つのメッセージ）

ステップ 2 では、**本物のロボットと同じ「型」**で、障害物をよけて走るロボットを作ります。
この文書では、「何のためにやるのか」と、本物のロボットが使う 2 つのメッセージ（`/scan` と `/cmd_vel`）を説明します。

## 1. 何のためにやるのか

**ノイズのあるセンサーの値から、ロボットが安全に判断する頭脳を、本物と同じ部品で作れるようになる**ことが目的です。

具体的な使いみちは、ロボット掃除機や、倉庫の荷物を運ぶロボットです。

| 現実のロボット | この演習での対応 |
|---|---|
| 本体の上のレーザーセンサー（LiDAR）が、まわり 360° の距離を測る | `/scan`（`LaserScan`） |
| 「前に壁がある → 曲がる」と判断するソフト | `avoider`（これから書く頭脳） |
| モーターに「前進○ m/秒、回転○ rad/秒」と指示する | `/cmd_vel`（`Twist`） |
| 家具や壁のある部屋 | `room_sim` が作る 2D の部屋 |

### 入門編との違い

入門編（[basics](../basics/02-robot-exercise.md)）は、名前も型も自作でした。
今回は、**ROS 2 で決まっている型**を使います。

| | 入門編 | ステップ 2（本物と同じ） |
|---|---|---|
| センサーの値 | `distance`（`Float32`、数字 1 つ） | `/scan`（`LaserScan`、**360 個の配列**） |
| 動かす指示 | `cmd`（`String`、`FORWARD` など） | `/cmd_vel`（`Twist`、**速さの数字**） |
| 世界 | 1 本の廊下（1 次元） | 障害物のある部屋（2 次元） |
| 見え方 | 文字の表示 | ブラウザで見える図 |

型が本物と同じなので、あとで書く頭脳は、**ほぼそのまま、本物のロボットや、本格的なシミュレータ（Gazebo）でも動かせます**。
これが、ROS 2 の強みです（部品を差し替えられる）。

入門編で学んだこと（ノイズ、移動平均、ヒステリシス、状態を持つノード）は、2D でもそのまま使います。

## 2. 全体の構成

```
room_sim ──/scan (LaserScan)──→ avoider（これから作る）
   ▲                                │
   └────── /cmd_vel (Twist) ←───────┘
   │
   └─ 部屋の図を 1 秒ごとに書き出す → output/index.html → ブラウザ
```

| ノード | 役割 | 状況 |
|---|---|---|
| `room_sim` | 部屋の世界。ロボットの位置を持ち、`/cmd_vel` で動く。LiDAR を真似て `/scan` に送る。図も書き出す | **できた**（[02](02-room-sim.md)） |
| `avoider` | `/scan` を読んで、障害物をよける指示を `/cmd_vel` に出す頭脳 | これから、あなたが書く |

## 3. `/scan`（`LaserScan`）: まわりの距離の配列

LiDAR は、レーザーを出して、はね返ってくるまでの時間で距離を測るセンサーです。
ロボットのまわりを、ぐるっと 1 周測ります。

```
        90°
         │
 180° ──🤖── 0°（正面）
         │
        270°
```

### 3.1 なぜ 360 本か

円を 1 周すると 360°（角度の単位）だからです。1° ごとに 1 本なら、360 本になります。
（365 は、1 年の日数です。角度の 1 周とは関係ありません。）

360 本は「決まり」ではなく、選んだ数です。本物の LiDAR は、機種で違います（0.5° ごとなら 720 本）。
だから、`ranges` の長さは、決め打ちせずに、次の式で求めると安心です。

```
本数 = (angle_max − angle_min) ÷ angle_increment
```

### 3.2 主なフィールド

| フィールド | 意味 | この演習での値 |
|---|---|---|
| `ranges` | 各レーザーの距離の配列（m） | 360 個 |
| `angle_min` | 最初のレーザーの角度（rad） | 0.0（正面） |
| `angle_increment` | レーザーどうしの間隔（rad） | 0.01745…（= π/180 = 1°）。実測で確認 |
| `range_min` | これより近いものは、測れない | 0.1 m |
| `range_max` | これより遠いものは、測れない | 12.0 m。実測で確認 |

**`ranges[0]` が正面**、`ranges[90]` が左、`ranges[180]` が真後ろ、`ranges[270]` が右です。
角度は、**真上から見て、反時計回りに増えます**。

### 3.3 `inf`（無限大）

`range_max` より遠くて、測れなかったレーザーは、距離の代わりに **`inf`** が入ります。

```
開始位置 (10, 10) の部屋（20 × 20）で、range_max = 12 のとき
  ranges[0]  = 10.0     正面の壁まで 10 m
  ranges[45] = inf      斜め前の角まで 10√2 ≈ 14.14 m。12 を超えるので inf
```

`inf` は、計算にそのまま混ぜると、答えも `inf` になって壊れます（`inf` と足し算すると `inf`）。
フェーズ 3 で、`inf` の扱い（無視する、遠いとみなす、など）を、自分で決めます。

## 4. `/cmd_vel`（`Twist`）: 速さで指示する

入門編では、`FORWARD`（前へ）のような**言葉**で指示しました。
本物のロボットは、**速さの数字**で指示します。

| 欄 | 意味 | 単位 | たとえ |
|---|---|---|---|
| `linear.x` | 前に進む速さ | m/秒 | 車のアクセル |
| `angular.z` | 回る速さ | rad/秒 | 車のハンドル |

`z` は、真上（天井）に向かう軸です。**真上から見て、その場でくるっと回る速さ**が `angular.z` です。

| `linear.x` | `angular.z` | ロボットの動き |
|---|---|---|
| 0.5 | 0 | まっすぐ進む |
| 0 | 0.5 | その場で、反時計回りに回る |
| 0 | −0.5 | その場で、時計回りに回る |
| 0.5 | 0.5 | 進みながら曲がる（カーブ） |

### 4.1 「0.5」は、速さであって、1 回に進む距離ではない

| 数字 | 意味 | 単位 |
|---|---|---|
| `linear.x: 0.5` | **速さ**（1 秒たつと、0.5 m 進む） | m/秒 |
| 0.1 | `room_sim` の 1 歩の時間 | 秒 |
| 0.5 × 0.1 = **0.05** | 1 歩で進む距離 | m |

自転車で言うと、「時速 18 km」は、1 時間で 18 km 進む速さですが、1 分では 0.3 km しか進みません。
同じように、`room_sim` は 0.1 秒ごとに更新するので、1 回の更新では 0.05 m だけ進みます。
それを 10 回（1 秒）重ねて、0.5 m になります。

### 4.2 角度の単位 rad（ラジアン）

| ラジアン | 度 |
|---|---|
| π ≈ 3.14 | 180° |
| 2π ≈ 6.28 | 360°（1 周） |
| 0.5 | 約 28.6° |

`angular.z: 0.5` は、「1 秒に 約 28.6° 回る」という意味です。

回る角度は、次の式で出せます（「速さ × 時間 = 距離」と同じ形です）。

```
回った角度 = 回る速さ × 時間
```

## 5. 本物のロボットとの対応

| この演習 | 本物 |
|---|---|
| `/scan` | LiDAR（RPLIDAR など）が出す `/scan` |
| `/cmd_vel` | 走行指令。TurtleBot3 や、Nav2 が出す `/cmd_vel` |
| `room_sim` | モーターとタイヤ、LiDAR（ハードウェア） |
| `avoider` | 障害物回避のソフト |
