# 06. ノイズと、最小値・平均・移動平均（フェーズ 3）

`/scan` にノイズを足すと、`avoider` の「前方の最小値」は、どうなるのか。
最小値、平均、移動平均を、**予想 → 実測**で比べた記録です。

入門編の [03. ノイズ・チャタリング・フィルタ](../basics/03-noise-and-filters.md) の考えが、**配列（360 個）を使う 2D でも、そのまま通じる**ことを確かめます。

## 1. ノイズを入れる

`room_sim` の `noise` パラメータで、`/scan` の距離に、ノイズを足します（[02](02-room-sim.md#6-パラメータ)）。

| 項目 | 内容 |
|---|---|
| `noise = 0.5` の意味 | **測れた距離それぞれ**に、**−0.5〜+0.5 m** の乱数を足す（レーザーごとに、別の値） |
| `inf` | 足さない（測れなかったものは、そのまま） |
| 初期値 | 0.0（ノイズなし）。`room_sim` を再起動すると、0.0 に戻る |

```bash
ros2 run room_robot_pkg room_sim --ros-args -p noise:=0.5    # 起動時に指定する
ros2 param set /room_sim noise 0.5                          # 動いている間に変える
```

## 2. 最小値は、ノイズで「かたよる」

### 予想問題

`noise=0.5` で `avoider`（最小値のみ）を動かすと、最初に回り始める `x` は、ノイズなし（18.52）と比べて、どうなるか。

| | 予想 | 実測 |
|---|---|---|
| あなたの答え | **C: もっと手前** | **平均 18.06**（200 回: 18.01〜18.10）✅ |
| 実機のノード（3 回） | | 18.04、18.07、18.04 ✅ |

200 回ぜんぶ、ノイズなしより手前でした。「たまたま」ではなく、**必ず手前**になります。

### 理由

「ノイズがプラスされる」は、半分だけ合っています。ノイズは**プラスにもマイナスにも**なります。それでも手前になるのは、**最小値を使っているから**です。

```
61 人が、ものさしで、壁までの距離を測る。みんな ±0.5 m の誤差がある。
その中から「いちばん短く測った人」の値を採用すると、いつも、短めになる。
```

61 本もあれば、1 本くらいは、「ほぼ −0.5」の誤差が出ます。最小値は、その 1 本を選ぶので、**実際より約 0.5 m 近く見えます**。

| 計算 | 値 |
|---|---|
| 一様な誤差（幅 1.0）の最小値のかたより | 約 −0.5 + 1.0 ÷ (61 + 1) ≒ **−0.48 m** |
| 回り始める本当の距離 | 1.5 + 0.48 ≒ 1.98 m（壁から。`x` ≒ 18.02） |
| 実測 | 18.01〜18.10（計算）、18.04〜18.07（実機） |

「1.5 m でよける」つもりが、**「約 2 m でよける」ロボット**になりました。安全寄りですが、必要以上に、手前で回ります。

## 3. 平均は、かたよらないが、危ない

### 予想問題

`nearest = min(front)` を、`sum(front) / len(front)`（61 本の平均）に変えると、最初に回り始める `x` は、どうなるか。どちらが安全か。

| | 予想 | 実測 |
|---|---|---|
| あなたの答え | **C: もっと壁に近づいてから。安全じゃない** | **18.57**（100 回: 18.49〜18.64）✅ |

### なぜ、壁に近づくのか

ノイズの＋と−は、平均で打ち消し合うので、**かたよりはありません**。ただ、斜めのレーザーは、**正面より遠い壁**に当たります。

```
正面 0°:  壁まで d
斜め 30°: 壁まで d ÷ cos30° ≒ 1.15 d
```

61 本の平均では、**正面の約 1.05 倍**に見えます（計算で確認: 1.051）。

```
1.5 ÷ 1.051 ≒ 1.43 m → 壁まで 1.43 m になって、はじめて回る
```

### なぜ、安全ではないのか

| 理由 | 内容 |
|---|---|
| ① 細い物を、見逃す | 61 本のうち 1 本だけ 0.5 m、残りが 3.0 m だと、最小値は 0.50（危ない）だが、平均は **2.96**（安全に見える）。ポールや椅子の脚が、これにあたる |
| ② 回るのが遅い | 実際に、60 秒の計算で、**押し当たり**（本当の最近接 0.30 m = ロボットの半径）が起きた |

平均は、「全体の様子」を見る道具です。「いちばん近い 1 本」の危なさは、薄めてしまいます。

## 4. 移動平均（時間の方向）は、揺れだけを減らす

### 空間の平均と、時間の平均

| | 何を平均するか | 使いみち |
|---|---|---|
| 空間の平均 | **いまの 61 本** | 危ない（上のとおり） |
| 時間の平均（移動平均） | **過去 N 回の、最小値** | 揺れを減らす |

入門編の移動平均と、同じ考えです。`avoider` では、**最小値を作ってから**、その過去 N 回分を平均します（最小値の「安全寄り」を残したまま、揺れだけを減らします）。

### 予想問題

「最小値」を、過去 5 回分で平均すると、最初に回り始める `x` は、最小値のとき（約 18.05）から、どうなるか。

| | 予想 | 実測 |
|---|---|---|
| あなたの答え | **C: もっと壁に近づく（18.57 より先）** | **18.12**（A: ほぼ同じ） ✗ |

### 予想とずれた理由

| 項目 | 内容 |
|---|---|
| あなたの理由（「過去の値も平均されるので」） | **仕組みは、正しい**。近づく間、過去の最小値は、いまより遠いので、回るのが少し**遅れる** |
| ずれた所 | **大きさ**。遅れは 2 回ぶん（N=5 の平均は、約 2 回前の値）で、2 × 0.03 ≒ 0.06 m。実測 18.12 − 18.05 = 0.07 ✓ |

さらに、**かたより（約 −0.48 m）は、毎回、同じ向き**に出ます。時間で平均しても、**消えません**。

| ノイズの種類 | 移動平均で |
|---|---|
| 毎回バラバラに揺れる部分 | **減る** |
| 毎回、同じ向きにずれる部分（かたより） | **減らない**（18.05 のまま。18.52 には戻らない） |

### N を変えて比べる

`noise=0.5`、計算（各 100 回、60 秒）。

| 方法 | 最初に回り始める `x` | 回り始めた回数 | 本当の最近接 |
|---|---|---|---|
| 最小値のみ（ノイズなし） | 18.52 | 18.0 | 0.78 m |
| 最小値のみ | 18.05 | **24.2** | 0.99 m |
| 最小値の移動平均 **N=5** | 18.12 | **10.7** | 0.92 m |
| 最小値の移動平均 N=20 | 18.35 | 3.7 | 0.89 m |
| 61 本の平均 | 18.57 | 16.6 | **0.30 m**（押し当たり） |

入門編と同じ**トレードオフ**です。

| N | 揺れ | 遅れ（x のずれ） |
|---|---|---|
| 1 | 多い | なし |
| **5** | **少ない** | **小さい（+0.07）** |
| 20 | ほぼない | 大きい（+0.30） |

> 訂正: 以前、「ノイズで揺れ（回数）は増えない」と言いました。40 秒では、16 → 16.7 で差が小さかったためです。60 秒で測ると、18.0 → 24.2 に増えます。

### 遅れは、「やめる」にも出る

あなたの実機のログで、はじめの回転は、次のとおりでした。

| | はじめの回転 |
|---|---|
| ノイズなし・最小値のみ | θ 3° → **40°** |
| ノイズ 0.5・移動平均 N=5 | θ 3° → **49°**（約 9° 多く回った） |

前があいても、過去の「近い」値が、平均に少し残るので、**回りすぎます**。0.5 rad/秒 × 約 0.3 秒 ≒ 9° で、合っています。**遅れは、「回り始め」にも「やめる」にも出ます。**

## 5. コード

入門編の `brain.py` と同じ道具（`deque`）を使います。

```python
from collections import deque
...
    def __init__(self):
        super().__init__('avoider')
        self.history = deque(maxlen=5)                       # 最小値を、5 個まで覚える
        ...
    def on_scan(self, msg):
        front = msg.ranges[0:31] + msg.ranges[330:360]
        nearest = min(front)                                 # 今回の最小値
        self.history.append(nearest)                         # 覚える（6 個目で、いちばん古いものが消える）
        dist = sum(self.history) / len(self.history)         # 平均（最初の 4 回は、5 個たまっていないので、len で割る）
        out = Twist()
        if dist < 1.5:                                       # 判断には、平均を使う
```

| 注意 | 内容 |
|---|---|
| 足す値 | **今回の最小値**（`brain.py` の `msg.data` に当たるもの） |
| `inf` | 前方の 61 本が、すべて `inf` だと、最小値も平均も `inf` になる。「何もない」として前進するので、いまは問題にならない |

## 6. 実機で確かめた結果

`noise=0.5`、`avoider` は N=5。

| 項目 | あなたの実機 | 私の実機テスト（3 回、別ドメイン） | 計算 |
|---|---|---|---|
| 最初に回り始めた `x` | **18.13** | 18.13、18.13、18.13 | 18.12（18.10〜18.16） |
| 60 秒間の「回り始めた」回数 | **8** | 10、10、10 | 10.7 |

最小値のみ（ノイズなし）の 18 回から、**約 3 分の 1 以下**になりました。

## 7. まだ残っていること

揺れは、ゼロではありません（60 秒に 8〜10 回）。境界（1.5 m）の**上**で、判断が行ったり来たりするからです。
入門編と同じ、**ヒステリシス**（回りはじめる線と、やめる線を、ずらす）で、さらに減らせます。フェーズ 4 で、自分で書きます。

## 9. つまずいたこと

| つまずき | 原因 | 対処 |
|---|---|---|
| `grep: /tmp/sim.log: No such file or directory` | ログは、**コンテナの中**にできる。Mac 側のタブで `grep` した | コンテナの中のタブ（`root@...:/#`）で実行する |

## 用語集

| 用語 | 意味 |
|---|---|
| かたより（バイアス） | 毎回、同じ向きにずれること。平均しても消えない |
| 揺れ（ジッター） | 毎回、バラバラにぶれること。平均すると減る |
| 移動平均 | 過去 N 回分を平均する。N が大きいほど、揺れは減るが、遅れる |
| `deque(maxlen=N)` | N 個まで覚える入れ物。N+1 個目を足すと、いちばん古いものが消える |
